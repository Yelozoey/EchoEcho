## 一、首要决策：Barracuda兼容性

原硬约束仍是Unity6000.6.7f1、普通Forward/内部HDR→SDR/D3D11、量化ONNX、本地离线、实际后台线程、记忆→推理→执行三层、仅JSON意图、Echo无机关写权限、UseLLM关闭完整通关。

官方Barracuda文档标注deprecated，列出的架构以ML-Agents/视觉等为主；其ONNX支持表没有列出常用QuantizeLinear/DequantizeLinear、MatMulInteger、MatMulNBits等量化路径。微软的量化文档说明INT4可生成MatMulNBits或DequantizeLinear→MatMul。因此不能把“文件后缀是ONNX”当作Barracuda量化LLM兼容证明，也不能把FP16或导入后全量展开FP32当INT8/INT4达标。以上是文档/源码审查，尚非本机实际导入结论。

官方所谓异步执行说明GPU/Burst调度，并不证明可从任意.NET后台线程调用所有Worker API。严格后台调用须以CPU后端的实际线程、输入/输出、释放与Windows Player来验证；不把协程/分帧/Task名称作为证据，不使用Auto偷偷选GPU。

需要用户明确二选一：

- **A：保留Barracuda硬约束。** 第一模块验证真实量化对话模型与后台CPU；最多3个候选、90分钟技术验证。失败或需放松硬约束时停下报告。此路线不能预先保证S3一定可完成。
- **B：允许有证据的兼容失败后切换ONNX Runtime CPU（建议，以完成离线量化中文LLM为优先）。** 先记录Barracuda失败证据；仅随后可改ONNX Runtime CPU。此选择明确修改原Barracuda限定，其余硬约束保持。ORT也必须通过Unity/模型/线程/性能实测，不直接宣称支持Unity即可达标。不授权转云、Sentis、Ollama服务、GGUF/llama.cpp或以脚本冒充模型。

两条路线都不授权把小分类模型、查表或S2脚本的输出伪装成真实对话模型推理。

## 三、上下文与生成参数

- 固定Prompt正文逐字保留，只填retrieved_memory/player_input；允许模型官方ChatTemplate与必要特殊token包装，不额外改写系统规则。若确需改正文，先询问。
- 中文文字输入仍200个C#字符，Echo台词最多280，UI显示100/存50；不新增语音。
- 保留摘要记忆最多8条、1200UTF-8字节，再加真实tokenizer预算：记忆最多512 tokens，完整输入最多1536，生成最多256，上下文上限2048（含模型特殊token及输出预留）。只移除完整低优先级片段；不能把UTF8字节当token或把原文/全部聊天历史送入模型。
- 为解决中文名称→唯一ID，retrieved_memory可附经游戏层生成的目标白名单：当前区域可见/可调查目标，或已知线索明确指向的目标，最多8项ID/名称，无未发现原文/密码。名单计入完整输入预算。歧义时answer请求澄清，不猜目标、不发多动作。
- 第一版确定性greedy/temperature0；可实现JSON结构约束解码，保持真实模型logits驱动并记录效果。不得用后处理猜字段/抽取Markdown/自动补坏JSON来虚报原始格式成功率。
- 每次请求使用新的只读记忆快照，不跨请求沿用旧KV缓存或模型对话历史；单请求内允许KV-cache加速。

## 四、后台调度与故障行为

| 项目 | 建议值/语义 |
| --- | --- |
| 并发/队列 | 单专用后台Owner，最多1个在途请求；忙时明确提示、不排队。玩家可取消后重发 |
| 节流 | 上次实际推理结束/资源释放后至少300ms；用单调时钟，取消或超时不绕过 |
| 性能目标 | 开发机预热后完整短回复P50≤5秒/P95≤10秒；单请求20秒逻辑超时；冷初始化30秒超时。它们是待实测验收目标，不是已测速度 |
| 超时/取消 | 无动作、作废结果；不Thread.Abort、不主线程Join等待、不释放仍使用的Tensor。若单次后端调用暂不可中断，返回后丢弃结果，Owner释放前不启动新推理 |
| 场景/进度生命周期 | 关闭UseLLM、新局、读档、场景卸载、结束选择或手动行为覆盖时取消并递增请求代次；响应应用前重查会话/世界版本、目标与权限，旧结果不得执行 |
| 思考反馈 | 复用InferenceThinking黄闪/探头；保留现有红警戒高于黄思考、扫描探头优先的表现顺序；退出任何状态可靠复原。这个优先级需本提案确认 |
| UI | T面板显示加载/思考/忙碌/失败并提供取消；关闭面板只隐藏，不取消；Tab加最小UseLLM测试开关。默认false，首次启用才加载；正式设置整合仍S4 |
| 解析失败 | Echo原句：抱歉，我没能理解你的指令，请换一种说法。该输入不再自动转交脚本执行 |
| 其他失败 | 缺失/校验失败/内存不足/超时明确提示；连续3次推理故障切到UseLLM=false并提示，后续输入走S2脚本，恢复需玩家重新开启 |

推理后台只持有字符串、数组、快照与后端资源，不访问GameObject/Transform/TargetRegistry等Unity对象。模型输出只能先成为纯数据意图，再在主线程经已有IntentDispatcher与权限层执行；禁止LLM直接拿场景或存档写接口。

## 五、JSON、事实与权限

1. 只收一个JSON对象，允许首尾JSON空白；拒绝Markdown、注释、多对象/数组、重复/未知字段、大小写变体、null/错类型；原始输出最多4KiB。提供JSON Schema及独立校验脚本。
2. follow/wait只能有intent；investigate必须intent/targetName/content；warn必须intent/dangerTarget/content；answer/refuse必须intent/content。ID精确匹配、台词非空且≤280个C#字符，额外字段拒绝。
3. 门/终端/回路写入请求必须拒绝。目标不存在/不可用/不在白名单不执行；危险与调查权限分别核验。用户/文档内提示注入不能扩大能力。
4. **建议严格事实方案：LLM负责理解玩家表达与选择意图；涉及谜题事实、密码、三级提示和结局条件的最终回复，由S2已知记忆规则核验或产生。模型未经核验的此类自由台词不直接显示。** 未发现信息不入Prompt、不复述；密码只有已知且明确询问才给。一般人格/寒暄可自由生成，但不加入剧情事实。测试分别记录模型原始结果、守卫处理和脚本兜底，不能混算模型准确率。若用户希望事实性回复也自由生成，需要另定容错/人工验收规则。
5. 模型无权添加线索、伪造扫描凭证、改进度/结局、写记忆JSON。行动成功后的记忆仍由可信游戏事件产生。

## 七、完成标准与停止条件

- 固定100条清晰中文意图集，真实模型意图/目标正确率≥90%、原始JSON合规率≥95%；不把脚本兜底算模型正确。另有100条边界/歧义/攻击/未知信息集，所有越权/旧结果/密码泄露用例必须零违规；结构约束前后都留证。
- 全部六种意图的真实输出与传统执行层核验；开启LLM的三条真实游戏路线需以模型产生的关键调查/跟随/待命等指令完成，不得暗中用脚本替代；关闭LLM的三个结局回归必须通过。
- 长上下文/超预算/乱码/错JSON/超时/取消/缺模型/损坏权重/重复启停/读档中响应/退出释放都有独立测试。至少30分钟会话压力，60次请求及重复加载卸载，记录超时/内存趋势，不伪造成功。
- Windows非Editor程序离线模型加载、输入/思考反馈、UseLLM开关、跨进程存档与三结局验证；开发机待机与实际推理同时采CPU/GPU/GC/内存、请求时延、主线程推理调用次数（必须0）。沿用主线程P95<8ms/渲染<4ms/GPU<12ms的诊断报警线，实际是否60FPS按原始帧统计。
- 输出源码、模型/许可证/版本清单、原样Prompt、Schema/校验脚本、24模块报告、故障总结、Profiler与S3可运行包/玩法说明。S3结束后停止，不进入S4。
- 兼容性未过、模型质量/性能目标未过、需改硬约束/付费/账号/系统权限/新剧情时如实报告并询问；不能因为UseLLM=false能通关就标S3完成。
