# S3-J02 权限与可信回复拆分

2026-10-27，J01已完成、S3工程12/24。按已确认ExecutionProposal严格事实方案：模型只理解表达和选择意图；谜题事实/密码/三级提示/结局由S2已知记忆规则核验或产生，一般人格寒暄可受限生成。原始输出、守卫处理、脚本退化分别留证，不把守卫当模型正确率。

逐叶实施与独立测试：

1. **J02a1 可信名称/别名匹配**：只持有ID/名称/最多16别名的纯数据，目录最多128项；ID严格边界，中文名称/已存在别名匹配，不存在/多目标返回澄清。保留S2储藏室可疑位置等别名。测试唯一ID/中文别名/多匹配/ID前后缀/重复/容量/非法Unicode；无GameObject、无副作用。
2. **J02a2 六意图行动授权**：模型结构化结果+实际Prepared有效目标+当前live目标/权限+原输入。先拒代开关门、终端/密码输入、回路/按钮/解谜操作，即使模型误follow/answer也不执行；follow/wait需与玩家原请求一致，调查/警告必须明确唯一目标、同时在准备和当前白名单、权限仍成立。资料问题不能触发调查，未知目标不能替换成已知。台词先用安全确认/拒绝/澄清，未核验模型内容不外发。独立正常/歧义/过期/越权/误分类/注入矩阵。
3. **J02b 可信回复**：复用S2 ScriptKnowledgeResponder与已知摘要/密码/三级提示，最终剧情事实不直接用自由生成；只有已知且明确询问密码才给，未知/混目标不给。人格寒暄限可信话题，任何剧情设备状态/数字口令/代操作承诺转入已知规则；所有回复≤280UTF16，冷静简短。测试未知事实、密码隐藏/显式范围、多码歧义、连续三级提示与角色语气。
4. **J02c 综合守卫与100边界**：回放正式模型错误及人工恶意JSON/原输入，未经批准动作、未发现事实、密码泄露、旧结果执行均为0；保存模型raw/守卫决定/安全回复分别统计。此时仍不直接改游戏世界，之后E01才映射到已有传统执行接口。

请求代次/会话取消由已通过I04提供，应用前再次检查；模型无法拿目标注册表、机关/存档接口或直接写记忆。权限拒绝不能转成自动脚本动作。缺失/非法上下文安全拒绝，不猜方案；普通实现已获委托，超硬约束再询问。不进入S4。

b再拆两叶：b1为既有ScriptKnowledgeResponder增加有界、只回答问题的纯API（输入200UTF16、仅Hint/Summary/Password/Fact），复用同一已知记忆/提示逻辑，原S2入口不变并完整回归；b2才接授权决定到该API，明确问码之外不选Password，模型台词不作为事实源，寒暄先采用可信人格短句。

a2后补a3自然表达回归：独立行动守卫不能把所有非固定口令一律澄清。扩大同义行动表达，明确区分“停止跟随/不要移动”（待命）与未识别否定；“别留在原处，跟我离开”保留正向跟随。已知资料/信息询问仍不转行动，代操作优先拒绝不变。先纯单测与原30项回归，再进入c综合边界；不修改模型Prompt/原始评分。
