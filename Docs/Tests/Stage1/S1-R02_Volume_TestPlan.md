# S1-R02 Volume 独立测试计划

日期：2026-10-25；依据：用户已确认的 [v0.1 提案](../../Stage1/S1-R02_VolumeParameterProposal.md)。本文件为计划，不是通过结论。

环境：Unity 6000.6.7f1、URP 17.6.0、Windows x64、D3D11、1920×1080、内部 HDR/SDR 输出。最低基准 i5-8400/GTX1060 6GB/16GB/中画质60FPS；推荐 i5-12400/RTX3060 6GB/16GB/高画质60FPS；本轮当前机功能与增量测量不能代替两档硬件验收。

先测试 Profile/Prefab/Layer 与有效 Volume Stack；通过后再加入实际图像与 Player 测试。任何失败先记录修复，禁止推进其他模块。

| 用例 | 操作 | 断言/证据 |
| --- | --- | --- |
| R02-T01 | 检查项目资产与相机，更新运行 Volume Stack | ACES；Thin1/0.10/0.80；CA 0.02；Layer/Mask 匹配；Global 权重1优先级0；Override 显式设置 |
| R02-T02 | 观察中性基线与权重0，检查非目标效果 | 无意外 Bloom/暗角/运动模糊/景深/畸变；曝光、白平衡、对比度、饱和度中性 |
| R02-T03 | HDR 灰阶/彩色图卡，逐项开关 ACES | 实际图像变化与亮部层次可观察；截图与数值归档；保持 SDR 输出 |
| R02-T04 | 颗粒关闭、开启的多次采样；对照 Response 0 和0.8 | 噪声相对固定无颗粒参考存在；统计多次图像，不以单次随机差异下结论；亮区 Response 行为记录 |
| R02-T05 | 关闭/开启 CA，观察高对比边缘和字形图卡 | 图像存在极轻色差；保存细节供视觉确认；不宣称自动化已替人批准可读性 |
| R02-T06 | 注入非 PostProcessing Layer 的高优先级干扰 Volume | 正式测试相机有效 Stack 与图像不受干扰 |
| R02-T07 | 保存重开、重复创建、保护哈希、运行 R01 回归 | 参数/引用稳定，无重复资产；旧模板与 R01 场景内容未变；Pipeline 仅两项已批准输入字段变化 |
| R02-T08 | Windows x64 Development 独立场景构建和运行 | 实际 D3D11/1080p/SDR、Volume 参数及图像检查通过；退出码与日志留存 |
| R02-T09 | 同机同场景同分辨率关闭/开启后处理的交替采样 | 分别记录提交/读取与 GPU 可取得的计时；说明同步读取/编辑器影响、采样方法和无效样本；不捏造 GPU 数据或60FPS结论 |

原始数据与截图：`Docs/Tests/Stage1/Evidence/S1-R02/`。实际报告测试后另写。此前的兼容性警告 F-011 单独跟踪，不随本模块擅自更改 .NET 或第三方包。

实际图像测试在PlayMode运行，通过完整URP StandardRequest更新Volume并渲染；在浮点线性目标读取像素，PNG另做一次sRGB编码。8个不同frameCount的颗粒样本，每帧成对比较Response 0与0.8，使用无颗粒ACES参考。图卡覆盖HDR灰阶、蓝/橙色块、棋盘边缘和28/21/14像素高字形；字形仅供技术可读性检查，不能代替未来游戏字体与UI验收。

Windows验证构建临时启用Frame Timing Stats采集GPU时间，构建结束在finally恢复项目原值；不作为产品设置变更。独立Player先做图像验证，再以正常相机帧交替OFF/ON/OFF/ON，每组预热30帧、读取90帧，排除无效与重复时间戳。该短时诊断仅描述本机夹具增量，不设未经确认的性能验收阈值。
