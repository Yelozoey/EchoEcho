60 FPS 对应约 16.67ms 帧时间，这是总体预算，不代表 CPU/GPU 各自可串行占满此预算。S1诊断口径已在连续授权内落地：10秒实际API预热、三视点各300帧、nearest-rank百分位、完整保留900帧，预算/实际结果见[性能文档](Performance/S1_Performance.md)。目标硬件和最终画质档验收仍需后续确认与实测。编辑器帧率不能代替 Windows Player 的目标硬件性能测试。真实设备型号必须如实采集，不自行把推荐配置中的显存或型号改写成其他规格。

## 3. 游戏、场景与角色硬约束

- 类型：无战斗，探索、线索收集、环境解谜；完整流程 25–40 分钟，三个分支结局。
- 场景固定为五个连通箱庭：入口山谷 → 地面观测小屋 → 地下 A 实验室 → 通风通道 → 核心控制室。不是开放大世界。
- 阶段 1 首个制作箱庭是地面观测小屋；不据此擅自改变最终五区顺序。
- 美术复用免费 PBR 资源：Poly Haven、Quixel Megascans、Sketchfab 免费低模；逐资源核验实际免费状态、使用授权和署名条件。柔和风格化写实，冷蓝和灰色为主，少量橙红危险光。禁止大量手绘贴图，氛围依赖光照、局部体积雾和后处理。
- 玩家：WASD、鼠标视角、跳跃、E 交互、手电。S1已按连续授权采用第一人称、Input System+CharacterController。
- 日志自动归档笔记、数据、扫描结果；提供摘要给未来 LLM，原文不进入 LLM 上下文。
- 对话 MVP 仅文字；语音不在 MVP 内。
- Echo：观测站遗留小型轮式科研助理；能跟随、扫描线索、调查可疑地点、识别危险、整理线索、文字回答与提供推理提示。
- Echo 禁止替玩家完成解谜、自动开门或直接修改关卡机关状态；只能提供信息、移动调查/扫描和警告。
- Echo 四个行为模式：`follow`、`investigate`、`wait`、`warn`；`answer`、`refuse` 是额外对话意图，不增加行为模式。
- 表达：蓝灯平静、黄灯思考、红灯警戒；探头俯仰、轮子动画；不做面部表情。台词冷静、简短、理性、克制，不玩梗。

## 6. 强制三层 AI 架构

数据方向：记忆层 → LLM 语义推理层 → 传统游戏执行层。保留全局布尔 `UseLLM`；关闭时脚本 NPC 支持完整通关。阶段 1 不导入模型、不推理，执行层可独立运行。

### 6.1 记忆管理层

C#，本地 JSON 持久化。事件记忆是时间线，文本格式 `[编号] 事件简述`；线索库保存摘要、密码和关键标记；角色状态记忆保存已知危险、历史约定、Echo 对玩家的认知。

玩家提问时关键词检索，只把相关片段送入 Prompt；禁止灌入全部历史。久远、低优先级事件降权，限制总 Token。S2已确认手工摘要与关键词/同义词、最多8条和1200 UTF-8字节、S2独立单槽并与进度一致提交；普通排序/衰减数值逐模块先记录再测试。字节预算不冒充Token计数，S3模型确定后再用真实tokenizer验收。玩家日志原文与 AI 摘要分开保存/使用，不能互相替代。

### 6.2 LLM 语义推理层

必须 Barracuda、量化 ONNX、本地离线；不指定固定模型，须先验证模型算子、量化格式、内存、线程和目标硬件兼容性，不得自行改成 Sentis、远端 API 或云推理。所有推理在独立后台线程，禁止主线程推理；不能以 `async` 方法名冒充后台线程证明。

上次推理完成后至少等待 300ms 才允许新请求。推理期间黄灯闪烁、探头旋转。解析失败固定台词：`抱歉，我没能理解你的指令，请换一种说法。`

模型、推理后端、超时、取消和并发策略尚未确认；如 Barracuda 技术验证与约束冲突，必须先报告并询问，不得静默放宽要求。

固定 Prompt 必须直接使用，以下原样留存：

```markdown
你是Echo，废弃观测站的轮式机器人助手。
硬性规则：
1. 输出严格为JSON，禁止任何额外文字、解释、注释；
2. intent仅允许从列表选择：follow, investigate, wait, warn, answer, refuse
3. 字段说明：
- follow：跟随玩家，无额外参数
- investigate：必须带 targetName（游戏内物体唯一ID）、content（Echo台词）
- wait：原地待命
- warn：必须带 dangerTarget（危险物体ID）、content（警告台词）
- answer：content为回复玩家的台词
- refuse：content说明无法执行的理由
上下文记忆片段：
{retrieved_memory}
玩家输入：
{player_input}
```

合法示例：

```json
{"intent":"investigate","targetName":"power_panel_01","content":"我检测到供电面板信号异常，我前去扫描。"}
```

JSON Schema和校验脚本在阶段3实现；未知字段/大小写/无效目标/空台词等严格拒绝策略已由S3方案整体确认，按J01/J02逐模块实测，不重复询问已确认项。

### 6.3 传统游戏执行层

接收验证后的意图结构体；不依赖 LLM。A* / NavMesh 与动态障碍；距离和角度感知；行为树根节点按意图切换跟随、调查、待命、警告子树；轮子、探头、指示灯绑定状态。

S1已按连续授权采用Unity AI Navigation与专用Echo Agent、动态障碍及轻量C#行为树，均已独立实测。可疑目标、危险和机关的权限必须分离；扫描发现信息不能自行触发开门/完成谜题。
