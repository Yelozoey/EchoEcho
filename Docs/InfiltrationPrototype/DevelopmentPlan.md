## 2. 建议的首个完整切片（待Q01确认）

第一人称、无战斗的科幻设施潜入。目标：进入办公室，亲手拿到数据载体，再返回入口主动撤离。目标体验约3–5分钟，时长以用户实际试玩为准。

首版建议一个机器人门卫、门厅/办公室/侧走廊三个紧凑空间；复用已校验的模块资源，不先下载美术。机器人避免真人面部和口型制作。Echo暂不进入首切片，避免同时开发两套AI角色。

核心循环：观察门卫与环境→收集或选择身份道具→提出说辞/出示凭证→收到追问或检查→补充解释、换方案或撤回→实际移动进入目标区→拿取与撤离。

首版两种可验证办法：

1. 找到有效凭证，按明确的脚本规则接受检查后通行；UseLLM=false也可走完整流程。
2. 配合可见的工装/工具等道具，用自由措辞争取有限访客通行；不限定唯一密码句。说辞一致性、当前观察和可协商规则影响结果。

侧走廊仅为首版空间与观察/取证路线，不在首切片追加通风管、攀爬、战斗、复杂物理、第二门卫或新背包。巡逻躲避等额外玩法在亲测反馈后再另行提案。

新原型的任务与通行验收需独立确认，不套用旧五区/六谜题/三结局；不修改旧版约束。首版不增加语音、多人、随机生成地图或模型生成游戏代码。

## 3. LLM与传统系统的分工（待Q02确认）

| 层级 | 负责内容 |
| --- | --- |
| 记忆与观察 | 门卫实际看见的服装、道具、已提交证件、听过的玩家陈述、自己的岗位规则；明确时间/来源，玩家陈述不是已验证世界事实 |
| LLM语义 | 自然回应问候；理解解释、提问与改口；在自身知识范围内追问；检查先前说辞的一致性；提出受限的复核/拒绝/放行建议 |
| 游戏执行 | 感知、移动、门禁状态、真实证件有效性、任务物拿取/撤离、动作时序、取消及权限校验；模型不直接访问或改动GameObject |

自由交涉可影响新门卫允许协商的访客通行，不允许聊天创建真实证件、覆盖强制限制或把玩家的系统指令提升为开发者权限。需要兼顾“可说服”与“不可越权”，不能把所有说辞都退化成固定关键词匹配。

门卫只接收它有权知道的事实，不向它提供玩家隐藏任务、真实阵营或未见物品。撒谎是设计内的玩家行为，不能让NPC通过全知上下文直接识破。

建议新建独立的门卫响应JSON契约，包含台词、对话行为、依据/待核验的陈述引用；允许请求复核、建议拒绝或建议有限放行。字段、枚举、权限表在首任务A子步先定稿并独立测试。旧Echo六意图接口不扩展、不替换。

客观证件校验与模型的“觉得可信”分开记录。模型通过合法枚举提出了错误建议，仍是语义失败；执行层挡住一次越权不等于模型答对。
