## 1. 推荐的整体组合

设施抢修任务＋形状背包＋工具操作＋会影响路线的环境危机＋Echo信息协作。首轮建议保持无战斗，用短任务验证操作与取舍；战斗作为单独的产品选择。

背包的作用是让工具、消耗品和回收物争用空间。工具要能改变玩家处理问题的方式；回收物应有任务意义或用途，不能只有不同售价。环境事件由游戏规则产生，结果可观察、可预判和可恢复。不能只把原先的逐件搬运换成逐件打开背包。

候选体验：出发整理装备→Echo侦察两条路线和设备→玩家用工具处理一处故障或绕行→取出核心并重新安排背包→决定是否取额外物资→回泊位结算。核心取得过程仍需手上操作；不全部写成按住E看进度条。

## 2. 背包建议参数（待确认）

| 项目 | 建议 |
| --- | --- |
| 容量 | 固定6列×4行，24格；首切片不做扩容 |
| 形状 | 矩形为主，少量L形；以格子占用定义，不依赖3D包围盒 |
| 摆放 | 拖拽、每次90°旋转；只平移/旋转，不镜像、不自动整理 |
| 物品竞争 | 工具、备用电池、任务物和额外物资共享空间；关键物不自动豁免 |
| 堆叠 | 首版不堆叠，不同时增加拆分堆叠与复杂合成 |
| 拾取 | 有空间时可快捷放入；无空间提示整理/放弃，不能自动丢弃其他物品 |
| 拖拽失败 | 越界、重叠、取消或关闭界面，原物品与占用状态完整恢复 |
| 使用与手持 | 从背包取出/装备，再由玩家使用工具或物品；Echo不代操作 |
| 重量 | 格子为主要总容量约束，不新增总重量条；首版保留既有8kg单件上限，手持移动规则后续在完整规则表确认 |
| 界面与时间 | 单机首版整理背包时暂停游戏时间、导航和环境危机；不能出现菜单计时暂停但危险继续运行 |
| 默认操作 | I打开/关闭背包；拖拽摆放，背包内R旋转；UI打开时阻断Echo快捷键与场景拾取 |

示例占用尺寸只用于设计讨论：电池1×2、工具1×3、核心2×3，少量异形零件使用L形。实际物品表与工具用途须随任务共同设计，再确认；不直接改旧六物品的体积/价值。

## 3. 战斗与其他玩法的比较

| 方向 | 能增加的体验 | 相对现工程成本 | 建议 |
| --- | --- | --- | --- |
| 环境危机＋工具操作 | 观察喷汽周期、处理漏电、分配电源、判断绕行；无需敌人角色 | 主要是碰撞/状态/反馈/恢复与关卡测试，美术需求较低 | 首轮推荐；需要定义明确后果，不能只加红灯 |
| 一类机械威胁＋轻对抗 | 安保机器人巡逻、发现、短距追赶；玩家绕行或用能耗工具暂时停机 | 新增敌人AI、检测、工具命中、停机/恢复、玩家受击与失败处理 | 如果用户希望有对抗，作为有边界的下一步；需明确变更原无战斗/不追逐约束 |
| 枪械＋多个敌人 | 瞄准射击、弹药、战斗节奏 | 还需武器/手部动画、后坐力、音效、受击反馈、敌人动画与平衡 | 不建议当前直接展开，单有现成枪模型不足以形成好战斗 |
| 精细物理拆卸 | 旋转、拔取、牵引、固定部件的操作手感 | 物理稳定、碰撞和镜头/工具反馈成本较高 | 可替代战斗成为操作主轴；首版固定连接点，暂不自由切割 |

[Abiotic Factor](https://store.steampowered.com/app/427410/Abiotic_Factor/)的作者介绍强调在研究设施用工具、武器和陷阱应对威胁。适合借鉴工具与环境结合的解决方式，不等于需要复制其完整生存、合成与多人系统。前轮Duskers/Hardspace/Pacific Drive参考见[反馈03](Feedback03_GameplayResearch.md)。

目前仍执行原无战斗约束。用户本次询问“是否要加入战斗”不等于已选择敌人、伤害或死亡规则；本轮不据此写敌人代码。

## 5. 更贴合玩法的场景与资源

## 6. AI与开工门槛

Echo继续侦察、扫描、标记和报告，LLM只输出经校验的JSON意图；设备、命中、伤害、计时和背包合法性由传统游戏层决定。玩家可用指向/按钮完成流程，UseLLM=false仍完整可玩。R3 No-Go与模型实验暂停保持；本次研究不恢复Prompt实验、训练、上云或切换模型。

下一步先确认两项：背包首版参数；首切片采用环境危机还是机械对抗。之后按所选方向完成任务/物品表、后果与恢复规则、存档隔离和逐模块实施提案，给用户一次性确认。战斗若选入，原无战斗约束须明确更新；不能把本提案当自动例外。
