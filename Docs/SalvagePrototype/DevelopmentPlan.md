## 2. 已确认的首版体验边界

玩家进入小型废弃设施，亲自观察、拾取、携带、交付回收物。空间岔路、载重和电量构成取舍；Echo 调查、扫描、标记和报告，玩家决定带走什么及何时撤回。主操作为 WASD、鼠标、E 与指向/任务板，文字输入为可选补充，不增加语音。

先做约 5 分钟完整切片，再根据实际试玩决定是否扩成约 10–15 分钟求职 Demo。已明确独立于旧版时长/谜题/结局验收；时长仍须实测，不是开发工期承诺。

示例任务：玩家指定优先寻找电池，不处理远处设备；Echo 只在已知、获准的调查目标中选择并报告。环境改变、玩家取消或读档后，旧结果不再生效。任务建议不等于已执行动作。

原型不做战斗、敌人追逐、开放世界、多人联机、配音、真人表情、LLM 生成可执行代码或自由修改地图。用户已确认 Q02 单件手持/可放下/交付点确认，Q03 信息协作；Echo 不搬运、不自动开门、不改机关、不替玩家交付物资。

## 4. 保留的工程与性能基准

- Unity 6000.6.7f1；普通 URP Forward；内部 HDR、后处理转 SDR，关闭显示器 HDR 输出；Windows 10/11 x64、D3D11。
- 1920×1080；最低 i5-8400 / GTX1060 6GB / 16GB，中画质稳定 60 FPS；推荐 i5-12400 / RTX3060 6GB / 16GB，高画质稳定 60 FPS。只有对应实机证据才能写目标硬件通过。
- 记忆层 → LLM 语义层 → 传统执行层；只读快照、纯数据 JSON、C# 权限复核；后台线程不能访问 Unity 对象。
- 沿用已批准 ORT CPU 回退路线、本地 Qwen3-0.6B 量化 ONNX、默认 UseLLM=false。新玩法的真实模型能力未验证，旧六意图通过样例不能作为新任务规划通过证明。
- 原有输入/上下文预算先保留：输入 200 字符、回复 280 字符，记忆最多 8 条/1200 UTF-8 字节；上下文 2048 tokens、输入 1536、生成 256。改变预算需提案。
- 单后台 Owner、完成后至少 300ms 冷却、冷启动 30s/请求 20s 超时、取消与会话代次；不主线程 Join、不 Thread.Abort；候选对比不得混入脚本纠错成绩。
- 模型随包目标 ≤1GiB、AI 增量 RAM 目标 ≤3GiB、S3 新增资源上限 20GiB 保持。新美术接收另列实际占用，并检查与 S3 合计仍低于 20GiB，避免通过更换目录漏算。
- 美术：冷蓝/灰、少量橙红；免费 PBR，少量统一模块化资源；不大量手绘贴图。静态烘焙、实时动态光、阴影距离、合批/剔除、粒子池与扫描预算继续以实际实现验收。
