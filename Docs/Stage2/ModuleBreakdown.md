# 阶段 2 对话与记忆模块拆分

2026-10-25。用户已明确开始 S2。S1 的 31 个模块和 Windows 小屋 Demo 已交付；S2 首先确认记忆和玩法细则，继续一次开发一个模块、独立测试并归档后再进入依赖模块。

## 交付范围

三个主流程是记忆框架、文字对话、脚本玩法闭环。下面按现有需求暂拆为 30 个开发模块；谜题实例数量与剧情确认后，体量较大的模块还须继续细拆。模块数不等于谜题数。

五区顺序固定为入口山谷、地面观测小屋、地下 A 实验室、通风通道、核心控制室。S2 使用灰盒跑通全流程和三个结局，仍然 `UseLLM=false`。S3 才接入 Barracuda，S4 完成其余四区正式美术、Addressables 距离流送及最终画质档。

## 执行顺序与门禁

先确认并开发 M01，再按依赖逐个推进。记忆技术参数的确认不等于剧情已确认；剧情未定时不编造终局台词、密码或谜题状态。D06 与五区/谜题需要交替集成时，各自仍保留独立用例，不能以整合测试代替模块测试。

每个模块测试报告需记录环境、前提、步骤、期望、实际结果、证据、失败及复测、局限。现有最低和推荐硬件基准继续有效，开发机数据不能替代目标硬件 60 FPS 验收。测试继续通过 `Tools/MCP/module_tests.py` 的新鲜安全检查，不保存或丢弃用户未保存场景。

当前状态（2026-10-26）：30/30工程模块已开发、独立测试与归档，Windows五区/六谜题/三结局可玩。最终归档实走、跨进程恢复、无测试参数启动均exit0；性能1500有效帧全部0B GC。目标硬件60FPS、首次25–40分钟与人工IME体验仍待外部验收。S2执行结束，未进入S3/S4。
