# S2 M01 三类记忆数据与存储契约

2026-10-25，用户已选择“采用上述建议参数（推荐）”。此模块仅建立 C# 数据和内存存储，不改场景、不接对话、不写磁盘、不引入模型。

## 已确认边界

记忆分为事件、线索、角色状态三类。事件显示为 `[编号] 事件简述`；线索只保存摘要、已知密码和关键标记；角色状态记录危险、约定和对玩家的认知。日志原文仍由玩家日志保存，记忆接口不接收 `FullText`，也不保存 GameObject 或组件引用。

S1 `JournalStore.SummaryAdded` 和 `ExportSummaries()` 可作为后续 M04 入库来源。它们包含 ID、标题、分类和独立摘要，不能直接将整库作为 Prompt 上下文。真实扫描权限及设备只读规则继续由现有执行层保证。

## 已确认参数

| 项目 | 提案 |
| --- | --- |
| 类型 | `EventMemory`、`ClueMemory`、`CharacterMemory`，以及内存 `MemoryStore` |
| 通用 ID | 沿用项目稳定 ID 规则，小写 ASCII 字母起始，后接字母/数字/下划线，最多 64 字符 |
| 摘要 | 每条 1–120 个 C# 字符，拒绝空白；线索标题 1–80 字符 |
| 事件字段 | 稳定事件 ID、递增正整数编号、累计游戏秒数、摘要、优先级 |
| 优先级 | 低、普通、关键三级；具体检索权重在 M06 确认 |
| 线索字段 | 已发现线索 ID、标题、摘要、分类；可选已知密码与关键标记，只接受游戏事实显式赋值 |
| 角色状态字段 | 稳定状态 ID、危险/约定/玩家认知分类、摘要、可选关联目标 ID |
| 容量 | 事件 512 条、线索 128 条、角色状态 64 条 |
| 重复 | 相同 ID 且内容相同返回已知，不分配新编号、不重复发事件；冲突内容明确拒绝 |
| 角色状态更新 | 单独显式更新方法；禁止通过普通 Add 静默覆盖 |
| 达容量 | 明确返回容量不足，不自动删除已有事实；时间降权不等于删除记忆 |
| 顺序与快照 | 事件编号稳定；其他类型按首次入库顺序；快照不允许外部改动内部数据 |

密码和标记必须从已授权游戏数据获得，不解析或推断玩家输入中的声称事实。M01 只校验记录结构，M04/M05/D05 再实际验证未发现信息隔离。

类型和内存存储放入独立 `Assets/EchoStation/Memory/Runtime` 程序集，测试放入 `Assets/EchoStation/Tests/MemoryEditor`。记忆数据不依赖场景执行器，不给它开门、扫描显现或修改谜题的入口。后续 JSON DTO 单独定义，避免用反序列化直接绕过运行时数据校验。

字段校验统一复用 120 字符短文本预算；可选密码/关键标记为空或 null 时表示不存在，非空时同样最多 120 字符，空白拒绝。角色关联目标为可选稳定 ID。ID 按类别去重；事件编号由存储分配而非外部指定。事件时间、摘要或优先级变化也视为同 ID 内容冲突。普通只读列表可反映新入库数据，CaptureSnapshot 返回固定快照供后续后台读取；存储自身由主线程拥有，不承诺并发写。

## 后续模块参数提案

这些选择需确认后在对应模块写明详细契约，不属于 M01 已完成能力。

- M03：沿用单槽、版本、原子替换和上次有效备份的原则；独立记忆文件或与进度同次提交的具体方式，F03 前必须确认，防止新进度搭配旧记忆。
- M05：手工关键词/同义词和稳定 ID 匹配，不加分词模型、不自动改写摘要；无匹配返回空相关片段。
- M06：最多取 8 条，渲染后的完整上下文初期限制为 1200 UTF-8 字节；按相关性、优先级和游戏时间确定排序，不切断单条事实。**字节预算不是 Token 精确计数**；S3 选定模型后用真实 tokenizer 追加上限验收。
